# MISTNET 2.5.4 — финальная полировка перед публикацией

Публичный сайт MISTNET на Next.js / React. Сайт знакомит с продуктом и ведёт посетителя в уже работающий личный кабинет. Регистрация, пробный период, оплата, рефералы и управление подпиской остаются в Cabinet. Telegram — дополнительный канал, а не обязательное условие.

## Что входит в релиз

### Первый экран и визуальная композиция
- Сохранены оригинальный робот MIST, тёмная сетка, фирменные сине-голубые оттенки, глобус, серверная панель и исходный характер MISTNET.
- Пустая центральная зона Hero заполнена лёгкой SVG-визуализацией сети из четырёх локаций. Это статическая векторная графика с небольшой CSS-анимацией, не отдельная WebGL-сцена.
- Увеличен безопасный верхний отступ Hero относительно фиксированной шапки.
- Видимая надпись `Ctrl K` убрана из навигации; вместо неё — компактная кнопка поиска. Горячая клавиша `Ctrl+K` остаётся доступной.

### Пинг и мониторинг
- Пока `MISTNET_STATUS_ENDPOINT` не задан, интерфейс показывает демонстрационный пинг по локациям. Значения плавно меняются в строго ограниченном диапазоне 42–94 мс.
- Демо-значения явно помечены как демонстрационные. Они не являются измерением реальных серверов и не показывают их доступность.
- Если реальный API настроен и отвечает корректно, интерфейс показывает только полученные от него статусы/задержки, а пометки DEMO скрываются.
- Если API настроен, но недоступен или возвращает ошибку, демонстрационные значения не подставляются: отображается состояние «мониторинг недоступен».
- Контракт и переменные мониторинга описаны в разделе ниже.

### Конверсия и кабинет
- Основные CTA ведут на `https://lk.mistnet.ru` или подтверждённый Quick Purchase `https://lk.mistnet.ru/buy/mistnet`.
- START и TITAN ведут на общий Quick Purchase, где посетитель сам выбирает тариф, период и способ оплаты. Неподтверждённые query-параметры для выбора плана не используются.
- Вход и бесплатный тест доступны через личный кабинет; Telegram не обязателен.
- Telegram-бот и поддержка сохранены как дополнительные варианты.
- Функции кабинета не дублируются на маркетинговом сайте.

### Контент и доверие
- Отзывы, рейтинги и счётчики пользователей не добавляются до появления реальных данных.
- Не используются неподтверждённые обещания вроде «10 Гбит/с», «0 логов» или фиктивных 24/7 статусов.
- Условия обхода ограничений описаны без универсальных гарантий: доступность зависит от оператора, региона, маршрута и текущих ограничений.
- Сохранены тарифы, лимиты, доступные протоколы и четыре локации, указанные в материалах проекта.

### SEO и доступность
- Next.js metadata: Title, Description, Keywords, canonical, Open Graph и Twitter cards.
- `robots.txt`, `sitemap.xml`, JSON-LD для Organization / WebSite / Service.
- Брендированная 404-страница.
- Клавиатурный доступ к command palette, видимый фокус и улучшенные aria-подписи.
- `prefers-reduced-motion` отключает декоративную анимацию.

### Производительность
- Нативный скролл вместо Lenis.
- Three.js и GSAP загружаются как необязательные улучшения; базовый контент, меню, FAQ и CTA работают без CDN.
- WebGL-сцены запускаются после простоя браузера и около viewport; цикл рендера ограничен по FPS и приостанавливается вне экрана/при скрытой вкладке.
- На Save-Data, reduced-motion и слабых устройствах тяжёлые эффекты не запускаются.
- Для заполнения Hero используется SVG/CSS, без третьей WebGL-сцены.
- Next.js compression и базовые защитные HTTP-заголовки включены.

## Требования

- Node.js 20.9 или новее (рекомендуется Node.js 22)

## Локальный запуск

```bash
npm ci
npm run dev
```

Откройте http://localhost:3000.

В Windows можно запустить `start-dev.bat` двойным щелчком.

## Проверки перед публикацией

```bash
npm run qa:release
npm run start
```

`qa:release` последовательно запускает `qa:static`, ESLint, TypeScript typecheck и production build. Команда останавливается на первой ошибке и возвращает ненулевой код завершения. Перед ней один раз выполните `npm ci`.

Команда `npm run qa:static` выполняет независимую от npm-пакетов проверку структуры, внутренних ссылок, SEO-маршрутов, CSS-контрактов и сохранности `runtime.js`. Она дополняет, но не заменяет lint, semantic typecheck и production build. Перед загрузкой на сервер обязательно выполните production build в окружении, где доступны npm-пакеты. Не переносите `node_modules` или `.next` с Windows/Linux другой архитектуры — устанавливайте зависимости и собирайте проект непосредственно на целевом сервере или в совместимом build-окружении.

## Настоящий мониторинг (опционально)

Скопируйте `.env.example` в `.env.local` и задайте. Шаблон `.env.example` исключён из общего правила игнорирования `.env*` и должен оставаться в Git; реальные `.env.local` и другие файлы с секретами по-прежнему игнорируются:

```dotenv
MISTNET_STATUS_ENDPOINT=https://your-monitoring.example/api/nodes
MISTNET_STATUS_TOKEN=optional-secret-token
```

API должен вернуть JSON вида:

```json
{
  "updatedAt": "2026-10-30T14:30:00.000Z",
  "nodes": [
    { "id": "us", "status": "online", "latencyMs": 72 },
    { "id": "fi", "status": "online", "latencyMs": 31 },
    { "id": "nl", "status": "offline", "latencyMs": null },
    { "id": "tr", "status": "online", "latencyMs": 48 }
  ]
}
```

Допустимые ID: `us`, `fi`, `nl`, `tr`. Статусы: `online`, `offline`, `unknown`. Токен остаётся на сервере Next.js и не передаётся браузеру.

Если endpoint не задан, включается только подписанный DEMO-пинг 42–94 мс. Если endpoint задан, но не отвечает, демо-цифры отключены, чтобы не путать неисправность реального мониторинга с демонстрацией.

## Перед публикацией

1. Сверьте актуальность тарифов, лимитов и условий теста с Cabinet.
2. Проверьте переходы в личный кабинет и Quick Purchase с десктопа и телефона.
3. Выполните `npm ci`, `npm run lint`, `npm run typecheck`, `npm run build`.
4. Если нужен реальный статус серверов — задайте `MISTNET_STATUS_ENDPOINT`; иначе на сайте остаётся явно обозначенный DEMO-пинг.
5. Настройте TLS, домен `mistnet.ru`, reverse proxy и процесс Next.js на сервере.
6. После деплоя проверьте `https://mistnet.ru/robots.txt`, `https://mistnet.ru/sitemap.xml`, `/api/status` и OG-превью.

## Этап 3.5.1 — runtime hooks и typed integration boundary

Добавлены независимые клиентские хуки для media queries, reduced motion, видимости страницы, IntersectionObserver, ResizeObserver, rAF, таймеров, DOM-событий, focus-trap и внешних библиотек. Добавлены lazy loaders для GSAP / ScrollTrigger / Three.js, типизированная граница API мониторинга и утилита conversion tracking.

На подэтапе 3.5.1 старый `public/mistnet-runtime.js` и его подключение через `MistnetScripts.tsx` намеренно оставлены без изменений: интерактивность ещё не переключена на новые хуки. Это исключает двойное управление UI до подэтапа 3.5.2.

В архив включён актуальный CSS, ранее переданный пользователем в `mistnet-v2.css`; CSS-правила, добавленные на этапе 3.4.2 для извлечённых FinalCTA / HowTo / Pricing, сохранены в конце файла.

Зависимости npm не менялись. Проверка полного production build должна выполняться после установки зависимостей (`npm ci`) в рабочем окружении.
